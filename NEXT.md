# Очередь задач для следующих сессий

Файл существует ради экономии токенов: вместо того чтобы заново разбираться
в проекте, следующая сессия берёт отсюда готовый промпт и сразу работает.

**Правило.** Заканчивая сессию — обнови этот файл: вычеркни сделанное
(удали блок целиком), допиши то, что всплыло и осталось несделанным.
Промпт пишется так, чтобы его можно было скопировать в чистую сессию
и не объяснять контекст: путь, файлы, что проверить, чем закончить.
Если задача большая — делегируй её агенту, а не тяни в основную сессию.

Актуально на 10.09.2026.

## 1. Разъехались локальная копия и сервер

**Почему важно:** на `main` в GitHub канал живёт своей жизнью (автоматика
коммитит состояние по нескольку раз в день), а локальное дерево
`~/ПЛЕНКА` стоит на коммите месячной давности: 2 своих коммита
впереди, 352 позади, 92 изменённых файла. Пока это не разобрано, любая
локальная правка рискует затереть свежее состояние канала.

```
Проект «ПЛЁНКА»: папка ПЛЕНКА в домашней директории, ветка main. Общайся по-русски.

Локальное дерево разошлось с origin/main: 2 локальных коммита впереди
(4cc3925 «Вместо Крис — плёнка», 9d74a23 «Клипы: второй формат»), ~352 коммита
позади, около 90 изменённых файлов в рабочем дереве.

Разбери это расхождение. Порядок такой:
1. Сначала выясни, что из локальных правок ещё нужно, а что устарело.
   Автоматические коммиты сервера трогают только data/ и content/ — их
   локальные версии заведомо устарели, забирай серверные.
   Ценное лежит в src/ и prompts/: например, отправка отрывка трека
   в src/publish.py (send_audio), рамка обложки через src/card.py,
   src/clips.py, src/footage.py, src/host.py, assets/fonts.
2. Учти: assets/fonts/ вообще нет в репозитории на сервере, а src/card.py
   и src/stories.py без этих шрифтов падают. Если переносишь рамку обложки —
   переноси и шрифты (лицензии OFL рядом уже лежат).
3. Массовые git-команды (reset --hard, stash) в этом окружении блокируются
   классификатором. Рабочий обходной путь: свежий клон в scratchpad,
   копирование нужных файлов туда, коммит и пуш оттуда.
4. Ничего не публикуй в Telegram и не трогай data/ на сервере.

Закончи тем, что локальное дерево и origin/main сходятся, а всё ценное
из локальных правок либо запушено, либо явно перечислено как отброшенное.
```

## 2. Отрывок трека и рамка обложки не доехали до сервера

**Почему важно:** канал про звук, а в ленте у него сейчас только картинка
и текст. Локально `src/publish.py` умеет слать отрывок трека
(`telegram.send_audio`) с обложкой и подписью — в канале этого нет.

```
Проект «ПЛЁНКА»: папка ПЛЕНКА в домашней директории. Общайся по-русски.
Сначала выполни задачу 1 из NEXT.md (расхождение с сервером) — эта зависит от неё.

Локальный src/publish.py умеет отправлять пост отрывком трека через
telegram.send_audio (поля preview/track/artist в посте пишет src/compose.py,
функция _lead_track). На сервере этого нет. Перенеси связку целиком:
compose (_lead_track и поля в save_post), publish (ветка с send_audio),
telegram (send_audio, если его там нет), src/sources/*.album_tracks.

Проверь на живом посте из очереди сухим прогоном, не публикуя в канал:
python -m src.publish --dry-run. Отдельно проверь, что при протухшей
ссылке на отрывок публикация откатывается на обложку, а не падает.
```

## 3. МЕЖДУ СТРОК молчит: база цитат израсходована

**Почему важно:** в `data/subtext.json` три записи, и все три помечены `used`.
Рубрика в очередь больше не попадает вовсе. Пополняется она только руками
и намеренно: легальных источников для текстов песен нет, а выдуманная строчка
убивает доверие быстрее всего (см. CLAUDE.md).

```
Проект «ПЛЁНКА»: папка ПЛЕНКА в домашней директории. Общайся по-русски.

Рубрика МЕЖДУ СТРОК (prompts/rubrics/subtext.md) стоит: в data/subtext.json
все записи израсходованы. Задача — пополнить базу.

Правила, которые нельзя нарушать:
- В поле lines кладутся ТОЛЬКО реально существующие строки, которые ты можешь
  подтвердить источником. Не помнишь дословно — не пиши; тогда пусть lines
  будет пустым, а разбор пойдёт по notes (так рубрика тоже работает).
- В notes — проверяемые факты: что за трек, когда вышел, что вокруг него
  происходило. Никаких догадок о намерениях артиста.
- artist пишется ровно так, как имя стоит в data/artists.json.

Разберись с форматом по существующим записям, предложи владельцу 5-7 кандидатов
(артист, трек, на чём строится разбор) и спроси, какие брать, — вкус тут
решает он. После подтверждения добавь записи и проверь генерацию:
python -m src.compose --dry-run (модель не вызывается).
```

## 5. Непарный тег от модели убивает пост молча

**Почему важно:** проверено вживую на Bot API 10.09.2026. Ошибку разбора
вызывает не амперсанд (`Simon & Garfunkel`, `R&B;`, «хвост &» API принимает
как есть), а `<`: голый знак «меньше» уже экранируется в `sanitize`, но
незакрытый или перекрёстный тег — нет. `<b>жир` без закрывающего отвечает
`can't parse entities: Can't find end tag`, и пост не уходит вообще,
без записи в архив. В 78 постах архива и очереди такого пока нет, но
`sanitize` — защита именно от непредсказуемого вывода модели.

```
Проект «ПЛЁНКА»: папка ПЛЕНКА в домашней директории. Общайся по-русски.

В src/telegram.py функция sanitize() чистит разметку перед отправкой.
Голый «<» она экранирует (_BARE_LT), самопроверка — python -m src.telegram.
Незакрытый или перекрёстный тег она пропускает, а Telegram на нём отвечает
«can't parse entities» и не публикует пост вовсе — молча, без архива.
Воспроизводится на «незакрытый <b>жир» и «<i>курсив</b>».

Сравни два пути и выбери короткий:
1. Досчитывать пары в sanitize (стек открытых тегов, лишние — вырезать).
2. Запасной путь в telegram._call: если API ответил «can't parse entities»,
   повторить один раз без parse_mode и с вырезанными тегами. Дороже одним
   запросом, зато закрывает и те поломки, которых мы не придумали.

Проверь живьём на TELEGRAM_ADMIN_ID (сообщения за собой удаляй через
deleteMessage) и допиши случаи в _selftest внизу src/telegram.py.
```
