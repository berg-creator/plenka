Файл существует ради экономии токенов: вместо того чтобы заново разбираться

## 5. Непарный тег от модели убивает пост молча

**Почему важно:** проверено вживую на Bot API 10.09.2026. Ошибку разбора
вызывает не амперсанд (`Simon & Garfunkel`, `R&B;`, «хвост &» API принимает
как есть), а `<`: голый знак «меньше» уже экранируется в `sanitize`, но
незакрытый или перекрёстный тег — нет. `<b>жир` без закрывающего отвечает
`can't parse entities: Can't find end tag`, и пост не уходит вообще,
без записи в архив. В 78 постах архива и очереди такого пока нет, но
`sanitize` — защита именно от непредсказуемого вывода модели.

```
Проект «ПЛЁНКА»: папка ПЛЕНКА в домашней директории. Общайся по-русски.

В src/telegram.py функция sanitize() чистит разметку перед отправкой.
Голый «<» она экранирует (_BARE_LT), самопроверка — python -m src.telegram.
Незакрытый или перекрёстный тег она пропускает, а Telegram на нём отвечает
«can't parse entities» и не публикует пост вовсе — молча, без архива.
Воспроизводится на «незакрытый <b>жир» и «<i>курсив</b>».

Сравни два пути и выбери короткий:
1. Досчитывать пары в sanitize (стек открытых тегов, лишние — вырезать).
2. Запасной путь в telegram._call: если API ответил «can't parse entities»,
   повторить один раз без parse_mode и с вырезанными тегами. Дороже одним
   запросом, зато закрывает и те поломки, которых мы не придумали.

Проверь живьём на TELEGRAM_ADMIN_ID (сообщения за собой удаляй через
deleteMessage) и допиши случаи в _selftest внизу src/telegram.py.
```

data/memes.json, assets/meme/templates/, card.render_meme). Если нет — работай
в её рабочей копии .claude/worktrees/post-form, в устаревшее дерево ~/ПЛЕНКА
не пиши (см. задачу 1).

Что уже есть. Мем выходит картинкой: шаблон из каталога data/memes.json
(47 штук, key/name/when/source), надпись на самой картинке сверху и снизу
белым гротеском с тонкой обводкой, водяной знак канала в углу, текст поста —
подписью под фото. Модель отвечает полями top, bottom, text, picture
(src/llm.py, схема мема). Правила — prompts/rubrics/meme.md. Вид утверждён,
его не трогай.

Задача — чтобы мемы были смешными. Материал:
1. Реф владельца: ~/Downloads/photo_2026-09-11 13.19.13.jpeg — 3D-яблоко
   с руками, сверху «Иногда я говорю «хз»», снизу «Но я знаю». Его слова:
   «почти не имеет смысла, но смешнее». Это направление, а не шаблон для всех.

3. Вердикт владельца на пачку по новым правилам. Понравились:
   - енот застрял | Слушаю альбом с середины / Начало я не заслужил |

## 7. Релизы: протухшие, двойные и потерянные совместные

**Почему важно:** 11.09.2026 починили подпись релиза. Теперь исполнитель берётся
из магазина, а гостевые фиты и сольники участников не проходят
(collect.own_release, compose.store_checked). На том же прогоне всплыли три
соседние дыры, из-за которых посты про релизы по-прежнему могут врать или дублироваться.

```
Проект «ПЛЁНКА»: папка ПЛЕНКА в домашней директории. Общайся по-русски.
Работай в свежем клоне origin/main, не в ~/ПЛЕНКА (см. задачу 1).

Контекст: src/collect.py (store_credit, own_release), src/compose.py (plan,
store_checked), data/inbox.jsonl (merge=union — старые строки не переписывать,
фильтровать при чтении). Проверка вживую:
  python - <<'EOF'
  from src import compose; [print(p['artist'], '—', p['title']) for _, k, p, _ in compose.plan(200) if k in ('release', 'verdict')]
  EOF

1. Возраст. collect берёт релизы не старше 14 дней, а compose — любую
   неиспользованную находку. В плане 11.09 стояли «JAŸ-Z — In My Lifetime» от 26.07
   и «Marilyn Manson — One Assassination Under God - Chapter 2» от 14.08, то есть
   пост «вышло» про релиз полуторамесячной давности. Отсекать в plan по released_at
   (порог — тот же collect.RELEASE_MAX_AGE_DAYS или чуть больше, очередь идёт неделю).
2. Дубли. Один релиз приходит из iTunes и Deezer под разными названиями:
   «Slipknot — Arsenal» и «Slipknot — Arsenal - Single» оба прошли в план, выйдут
   два поста. Сверять по нормализованному названию (itunes._norm) и артисту,
   причём и в plan, и в сборщике.
3. Потерянные совместные. Соавтора iTunes по id не отдаёт, его ищем по имени,
   и при другом написании релиз отсеивается: «Ramil' & Basta — Сияй» не прошёл,

   id есть у всех основных артистов. Гостей (role Featured) по-прежнему не брать.

Каждый пункт — assert в compose._selftest на синтетических записях, без сети.
Проверки: python -m src.compose --selftest, python -m src.compose --dry-run.
В канал ничего не публикуй, compose без --dry-run не запускай.
```
