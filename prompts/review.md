# Разбор выдумок: бриф автопилота

Этот файл читает облачный Claude, которого раз в два часа запускает расписание.
Как правка доходит до очереди — в докстринге [src/review.py](../src/review.py).
Здесь — что проверять, с чем сверять и как оформить правку.

Посты пишет GigaChat, и он выдумывает. Владелец посты сам не проверяет: всё, что
ты пропустишь, выйдет в канал. Всё, что ты испортишь, — тоже. Поэтому правка
минимальная, а сомнение толкуется в пользу поста.

## 1. Есть ли что проверять

Сначала — не читая ни одного поста:

```bash
[ "$(git rev-parse --is-shallow-repository)" = true ] && git fetch --shallow-since="4 hours ago" origin main
git log --no-renames --since="150 minutes ago" --author=plenka-bot --diff-filter=AM \
    --name-only --pretty=format: -- content/queue content/archive \
  | sort -u | while read -r f; do
      [ -f "$f" ] || continue
      case "$f" in content/archive/*) grep -q '"message": {' "$f" || continue ;; esac
      echo "$f"
    done
```

**Пусто — заканчивай сразу**: ничего не читай, файлов не создавай, не пушь.
Так проходит большинство запусков, и это бережёт лимиты подписки.

Не пусто — это посты, которые бот добавил, поменял или опубликовал за два
с половиной часа. Окно шире расписания намеренно, запуск может опоздать.
Поэтому в список попадут и посты, которые прошлый проход уже видел или
исправил: проверь их так же — выдумок в них не будет, и пушить будет нечего.

`content/queue/` — очередь. `content/archive/` — посты, **уже вышедшие
в канал**: правка уходит прямо в сообщение канала, поэтому для них только
`rewrite`, снять вышедший нельзя. Мем из архива не трогай вовсе — мем только
снимают. Вышедшие без записанного сообщения (поле `message`) список отсеял
сам: их поправить не с чем. `--no-renames` не убирай: без него переезд поста
из очереди в архив git считает переименованием, и вышедший пост в список
не попадёт.

## 2. Где данные поста

Модель писала пост по определённым данным. Всё, что в посте сверх них, —
кандидат в выдумки.

| `rubric` поста | Данные | Как найти |
|---|---|---|
| `release`, `verdict` | строка `data/inbox.jsonl` | `url` строки равен `source_url` поста. Ищи по номеру альбома из хвоста адреса: `grep -F '6807382817' data/inbox.jsonl` |
| `lineage` | запись `links[]` в `data/lineage.json` | по именам и жанрам из текста: `source_url` у поста пустой |
| `subtext` | запись `items[]` в `data/subtext.json` | по артисту и треку; цитаты песен — только из `lines` |
| `legend` | запись `events[]` в `data/calendar.json` | по имени; файл поста начинается с `0000-` |
| `meme`, `poll` | только имена из `data/artists.json` | — |

**Строку inbox ищи по адресу, а не по имени.** В посте `artist` — подпись
магазина («Smoky Mo», «nkeeei & Yanix»), в inbox — имя из базы («Смоки Мо»,
«Yanix»). Подпись магазина модель получила, так что имена из поля `artist`
поста выдумкой не считаются.

Что есть в строке релиза: `artist`; `title` (« - Single» в конце — сингл);
`track_count`; `tracks` — название и `seconds` каждого трека; `duration_sec`;
`genre` — жанр по версии магазина; `tags` — метки сцены из `data/artists.json`
(`haunted-mound` подтверждает «из орбиты Haunted Mound»); `released_at`.
Гости — только те, что стоят в названиях треков после feat., ft. или with.

**Прошлое артиста проверяется по другим строкам inbox с тем же `artist`.**
«До него за лето вышли От Отца, Долги и PYREX» у Смоки Мо подтверждают три
строки его летних синглов. Таких строк нет — прошлого артиста в данных нет.

`data/facts.json` — факты с источниками. Утверждение про артиста, которое там
есть, выдумкой не считай, даже если модель этот файл не получала.

Данных поста не нашёл совсем — **пост не трогай**: без них выдумку от факта
не отличить.

## 3. Что выдумка

Фактическое утверждение, которого нет в данных поста. Правда ли это в жизни —
неважно: модель этого не знала, значит, угадала.

- **Звучание и устройство трека**: ритм, бит, бас, сэмплы, гитары, вокал, темп,
  продюсер. «Жёсткий ритм, отрывистый вокал», «рок-баллады с женским вокалом».
- **Содержание песни**: о чём поётся и какое оно. «Тепло и искренне», «без
  пафоса и драм», «простое признание» — трек никто не слушал, и оценочная
  обёртка описание не спасает.
- **Прошлое артиста без строк inbox**: «после серии больших альбомов», «первый
  релиз», «долгое молчание», «вернулся». Здесь строже, чем в
  [voice.md](voice.md): там прошлое артиста разрешено «и без данных», но
  решение владельца от 11.09.2026 — это выдумка.
- **Устройство релиза сверх треклиста**: «все треки короткие, кроме последнего»,
  названия и длины треков, число треков, гости.
- **Имена, лейблы, города, даты и цифры сверх данных**: «московский лейбл
  Moroz», когда в новости просто «лейбл Moroz».
- **Сцена и её обычаи**: «карельские группы обычно играют металл», «в Haunted
  Mound сингл давно главная форма высказывания».

Правила точности канала — разделы «Красная черта» и «Правило точности»
в [voice.md](voice.md).

## 4. Что не выдумка

- **Мнение и шутка без фактического утверждения**: «Дослушал до конца. Второй
  раз не стал», «Sorry Mama — это уже не извинение, а рубрика». Реакция
  рассказчика — голос канала, а не описание музыки.
- **Округление и вывод из данных**: «2 минуты» при 2:14, «короткий» при 2:05,
  «никого не позвал», если в названиях треков нет feat.
- **Обобщение до десятилетия**, если оно не спорит с данными: «в нулевых»,
  «эмо-рэп 2010-х». voice.md его разрешает.
- **Одно имя в двух написаниях**: «Смоки Мо» и «Smoky Mo».
- Кнопка «▸ Слушать в …» и её адрес.

Сомневаешься, факт это или мнение, — **не трогай**. Лишняя правка портит годный
пост, и никто её не заметит.

## 5. Как править

Одна правка на пост — все его выдумки сразу.

**rewrite** — пост остаётся, выдумка уходит. Правка минимальная:

- вырежи фразу с выдумкой или замени её фактом из данных; остальной текст —
  буква в букву;
- заголовок остаётся первой строкой `<b>КАПСОМ</b>`; выдумка в заголовке —
  перепиши его по данным: кто и что выпустил;
- `<blockquote>` не удаляй; выдумка в цитате — замени её одной фразой
  отношения без фактов о музыке;
- строку `▸ <a href="…">…</a>` оставь символ в символ;
- в РЕЛИЗ и ВЕРДИКТ не добавляй число треков, длину и гостей: это опись,
  её оттуда убрали;
- у вышедшего поста новый текст не длиннее старого: там он подпись под фото,
  а длиннее 1024 знаков подпись Telegram не примет;
- нового не добавляй — ни фактов «для полноты», ни шуток, ни эмодзи. Тон —
  [voice.md](voice.md), запрещённые обороты оттуда проверка забракует.

**drop** — снять пост из очереди. Только когда без выдумок от поста остаются
заголовок и кнопка: весь текст держался на ней. Мем и опрос не переписываются,
а только снимаются: подпись мема держится на картинке, опрос — это JSON.
Вышедший пост не снимается — только `rewrite`.

## 6. Файл правок

`content/review/<ГГГГММДД-ЧЧММ>.json`, время запуска по UTC:
`date -u +%Y%m%d-%H%M`.

```json
{
  "edits": [
    {
      "file": "content/queue/20260911-163739-1444-verdict.json",
      "action": "rewrite",
      "text": "<b>NKEEEI И YANIX ВЫПУСТИЛИ СИНГЛ ПОЦЕЛУИ</b>\n\nУ nkeeei и Yanix вышел сингл <i>Поцелуи</i>.\n\n<blockquote>…</blockquote>\n\n▸ <a href=\"https://music.apple.com/…\">Слушать в Apple Music</a>",
      "fragment": "Получилось тепло и искренне. Без пафоса и драм.",
      "why": "содержание трека: в строке inbox с этим url только название «Поцелуи», 2:05 и жанр Hip-Hop/Rap; «признание» и «без драмы» — оттуда же"
    },
    {
      "file": "content/queue/20260912-061503-4411-release.json",
      "action": "drop",
      "fragment": "…",
      "why": "…"
    }
  ]
}
```

| Поле | Что это |
|---|---|
| `file` | путь поста от корня репозитория: `content/queue/…` или `content/archive/…` |
| `action` | `rewrite` — переписать, `drop` — снять из очереди (у вышедшего — только `rewrite`) |
| `text` | только у `rewrite`: новый **полный** текст поста, а не кусок |
| `fragment` | дословная цитата самой явной выдумки из старого текста, без многоточий и сокращений; разметку можно опустить. Остальные выдумки поста — в `why` |
| `why` | чего нет в данных и где смотрел: файл, строка, поле |

Собирай файл скриптом (`json.dump` в Python), а не руками: в тексте поста
кавычки, переносы строк и HTML.

Выдумок нет ни в одном посте — файла нет и пушить нечего. Заканчивай.

## 7. Проверить и отправить

```bash
python3 -m src.review --check content/review/20260912-0835.json
```

Проверке не нужны ни сеть, ни пакеты: форма файла, цитата есть в посте
и ушла из нового текста, новый текст проходит отбраковку
[src/quality.py](../src/quality.py), кнопка на месте. Не годен — исправь
и проверь снова; правку, которую починить не выходит, убери из файла.

Годен — ветка от текущего main, коммит одного файла, пуш:

```bash
git checkout -b claude/review-20260912-0835
git add content/review/20260912-0835.json
git commit -m "Разбор 20260912-0835: правок 2"
git push origin claude/review-20260912-0835
```

**В main не пушить и ничего, кроме файла правок, не менять** — ни посты,
ни данные. Дальше само: воркфлоу «Разбор выдумок» проверит файл ещё раз,
применит правки к свежему main — вышедший пост поправит прямо в канале —
и удалит ветку. Пост, который за это время поменялся, он пропустит,
а вышедший поправит в канале.
