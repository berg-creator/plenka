# ПЛЁНКА

Автономный музыкальный канал в Telegram. Сам находит новинки, сам пишет посты,
сам публикует по расписанию. Работает на бесплатных мощностях GitHub — своего
сервера не нужно.

**О чём канал:** откуда взялся весь тёмный звук. Фонк вырос из мемфисского рэпа,
эмо-рэп — из гранжа, дрейн — из витч-хауса. Плюс новости сцены, разборы текстов,
вердикты новым релизам и мемы про индустрию.

---

## Как это работает

```
   Раз в 6 часов          Раз в сутки              4 раза в день
   ─────────────          ───────────              ─────────────
   Агент слежки     →     Генератор постов    →    Публикатор
   ищет новинки           пишет тексты             отправляет в канал
   (iTunes, Deezer,       (Claude API,             (Telegram)
    YouTube, 14 лент)      батчем — вдвое
                           дешевле)
```

Всё состояние — обычные файлы в этом репозитории. История постов лежит в git,
любой шаг можно откатить.

## Рубрики

| Рубрика | О чём |
|---|---|
| **ОТКУДА НОГИ** | Ниточка от современного трека к его предку. Главная рубрика |
| **ВЕРДИКТ** | Разнос или респект новому релизу. Без вежливой середины |
| **ИНФОПОВОД** | Новости сцены — мировой и русской |
| **МЕЖДУ СТРОК** | Разбор текста: отсылки, двойные смыслы, контекст |
| **МЕМ** | Юмор про музыку, индустрию и ру-рэп |
| **РЕЛИЗ** | Вышло что-то новое у отслеживаемого артиста |
| **ЛЕГЕНДА** | Годовщины. Выходит редко, поэтому должна быть лучшей |
| **ОПРОС** | Нативный опрос Telegram |

## Запуск

### 1. Ключи

Скопируй `.env.example` в `.env` и заполни:

| Переменная | Где взять |
|---|---|
| `ANTHROPIC_API_KEY` | console.anthropic.com → API Keys → Create Key. Это **не** подписка на claude.ai: ключ и счёт там отдельные |
| `GIGACHAT_CREDENTIALS` | developers.sber.ru → GigaChat API → проект для физлиц → «Ключ авторизации». Нужен как запасной генератор |
| `VK_TOKEN` | Группа → Управление → Работа с API → Ключи доступа. Права: стена, фотографии |
| `VK_GROUP_ID` | Короткий адрес группы, например `plenka_fm` — числовой id найдётся сам |
| `TELEGRAM_BOT_TOKEN` | `@BotFather` → `/newbot` |
| `TELEGRAM_CHANNEL_ID` | @username канала, например `@plenka_fm` |
| `TELEGRAM_ADMIN_ID` | `@userinfobot` пришлёт **число** — не @username |
| `LASTFM_API_KEY` | last.fm/api/account/create — бесплатно |
| `GOOGLE_API_KEY` | только если переключаешь провайдера на Gemini; **в России недоступен** |
| `SERPAPI_API_KEY` | serpapi.com → Manage API Key. Задел под активный поиск, кодом пока не используется |

Бот должен быть админом канала с правом «Публикация сообщений».

### 2. Установка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

### 3. Проверка

```bash
.venv/bin/python -m src.publish --check          # бот отвечает и пишет тебе в личку
.venv/bin/python -m src.sources.feeds --check    # какие ленты живы
.venv/bin/python -m src.collect --dry-run        # что нашлось, без записи
```

### 4. Первый запуск

```bash
.venv/bin/python -m src.collect                  # собрать новинки
.venv/bin/python -m src.compose --now 5          # написать 5 постов сразу
.venv/bin/python -m src.publish --target admin   # прислать первый пост себе
```

Когда посты начнут нравиться — переключай на канал:

```bash
.venv/bin/python -m src.publish --target channel --force
```

## Автономная работа на GitHub

1. Создай **приватный** репозиторий и запушь в него этот проект.
2. Settings → Secrets and variables → Actions → **New repository secret**.
   Заведи все пять ключей из таблицы выше.
3. Там же вкладка **Variables** → создай `PUBLISH_TARGET` со значением `admin`.
   Пока стоит `admin` — посты приходят тебе в личку. Меняешь на `channel`,
   когда готов публиковать по-настоящему.

Дальше всё идёт само:

| Что | Когда |
|---|---|
| Сбор новинок | каждые 6 часов |
| Генерация постов | раз в сутки ночью |
| Публикация | 4 раза в день |
| Истории ВКонтакте | раз в сутки |
| Клипы для VK и Shorts | по понедельникам, средам и пятницам |
| Годовщины | раз в сутки |
| Бот: кнопки модерации и разборы | каждые 5 минут |
| Сторож | раз в сутки, пишет только если что-то сломалось |

Любой шаг можно запустить вручную: вкладка **Actions** → выбрать → **Run workflow**.

## Канал, чат и комментарии

Три сущности, которые в интерфейсе выглядят похоже и постоянно путаются:

| Что | Зачем | Кто там пишет |
|---|---|---|
| **Канал** `@plenka_fm` | лента постов | только бот |
| **Чат обсуждений** | комментарии под постами | читатели |
| **Бот** `@plenka_fm_bot` | публикует посты, принимает кнопки модерации, выдаёт разборы | ты в личке |

**Комментарии и чат — одно и то же место.** Отдельной «системы комментариев»
в Telegram нет: к каналу привязывается обычная группа, Telegram сам пересылает
в неё каждый пост, а ответы на эту пересылку показываются под постом как
комментарии. Поэтому чат можно и не открывать напрямую — большинство читателей
попадёт туда через кнопку «Комментировать», даже не заметив, что это группа.

Что где включено, по интерфейсу не видно: половина настроек живёт в правах
бота, половина в свойствах чата. Показывает всё разом одна команда:

```bash
python -m src.setup --check      что настроено, а что нет и что делать
```

### Витрина канала

```bash
python -m src.setup --card                 показать пост-визитку
python -m src.setup --card --publish       опубликовать и закрепить
python -m src.setup --rules                показать правила чата
python -m src.setup --rules --publish      отправить в чат и закрепить
```

Визитка — единственный пост, который видит человек, зашедший по ссылке
до того, как что-то прочитал. Правила чата закрепляются в группе и заодно
объясняют, что это за место.

### Первый комментарий

Пустая ветка под каждым постом читается как «здесь никого нет», а писать
первым не хочет никто. Поэтому канал открывает ветку сам: бот отвечает
на пересланный пост одной строкой с вопросом по теме рубрики
(`src/comments.py`). Токенов это не стоит — вопросы готовые.

Работает только если **бот добавлен в чат обсуждений администратором**:
обычный участник пересылки постов не получает. Выключается строкой
`COMMENT_SEED` в `src/config.py`.

### Что нужно сделать руками

Через Bot API это недоступно — только из приложения:

| Что | Где | Зачем |
|---|---|---|
| Включить реакции | Канал → Управление → Реакции | Самое дешёвое действие читателя и первый признак живого канала |
| Право «Закрепление сообщений» боту | Канал → Администраторы → бот | Иначе визитку придётся закреплять вручную |
| Добавить бота в чат админом | Чат → Администраторы | Первый комментарий и удаление спама |
| Медленный режим 30 сек | Чат → Управление | Спам-боты приходят в привязанные чаты сами |

## ПРОЯВКА — разборы в личке бота

Канал говорит со всеми сразу, а этот сервис — с одним человеком. Смысл в том,
что пост не пересылают, а результат про себя пересылают: разбор вкуса приходит
картинкой, на ней подпись канала, и дальше она уходит в чужие сторис.

**Вход один: напиши что угодно.** Артиста, жанр, песню или сразу список —
разбор придёт на любой из них, порога в несколько имён нет. Отдельно
распознаётся только куплет: несколько длинных строк подряд бот разбирает как
текст песни, а не как список имён.

| Прислал | Получил |
|---|---|
| `Bones` | откуда вырос, на чём стоит, с чем рядом + карточка |
| `фонк` | к какому предку сходится жанр + карточка |
| `Molchat Doma — Судно` | разбор песни + карточка |
| `Bones, Sematary, Bladee` | что общего у списка + карточка |
| четыре строки из песни | что в них происходит на самом деле |

Порог в три артиста был первой версией и оказался ошибкой: он заставлял
вспоминать и собирать список до того, как человек хоть что-то получил, — а до
этого места доходят единицы. Один вопрос должен работать сразу.

Команд осталось две — `/start` и `/tekst`. Старые `/vkus`, `/nogi` и
кириллические `/вкус`, `/ноги`, `/текст` бот понимает при наборе, но в меню
не показывает: список из четырёх пунктов создавал впечатление, что надо
выбирать режим. Кстати, **в меню Telegram принимает только строчную латиницу**,
кириллическую команду туда не поставить в принципе.

**Кнопки объясняют, а не заменяют.** Нажатие — это отдельное событие, и на
медленном опросчике ответ на него придёт так же не сразу. Поэтому первое
сообщение бота уже содержит все три разбора с примерами: человек может ничего
не нажимать и сразу прислать список артистов. Кнопка запоминает выбранный
разбор ровно на одно следующее сообщение и отменяет догадку по форме — нажал
«Между строк», значит строки, даже если они похожи на имена.

Ссылка `t.me/plenka_fm_bot?start=taste` открывает бота сразу с инструкцией
к разбору вкуса. На ней держится кнопка под постом-визиткой канала.

**Разборы выдаются только подписчикам канала** — проверка через `getChatMember`,
бот уже админ, отдельных прав не нужно. Проверка идёт до обращения к модели:
неподписанный не стоит ни одного токена. Лимиты в `src/config.py`: по умолчанию
один разбор на человека в сутки и сорок на всех.

**Выключатель:** `SERVICE_DAILY_TOTAL = 0` в `src/config.py` останавливает
сервис для всех, кроме тебя. Канал при этом работает как работал — откатывать
ничего не нужно.

### Что ещё умеет бот

Под каждым разбором одного артиста стоят три кнопки — продолжение разговора
в одно касание, без набора руками.

| Кнопка | Что делает | Цена |
|---|---|---|
| 🎧 Что послушать дальше | 3–4 неочевидных имени с конкретной причиной | токены |
| 🆕 Что нового | свежие релизы из iTunes и Deezer со ссылками | бесплатно |
| 🔔 Следить | подписка: вышел релиз — бот напишет первым | бесплатно |

Рекомендации строятся **только** на кандидатах из Last.fm: список приходит
из статистики прослушиваний, модель лишь объясняет, почему именно эти. Своих
имён она не добавляет — это запрещено промптом. В выборку намеренно берутся
и ближайшие соседи, и что-то с краю: первое подтверждает вкус, второе его
расширяет.

Суточный лимит тратят только ответы, идущие через модель. «Что нового» —
выборка из магазина, брать за неё квоту было бы враньём.

Командами то же самое: `/sovet`, `/novoe`, `/slezhu` (список слежения),
`/stop` (очистить).

### Где лежат данные о людях

**В отдельном приватном репозитории.** Этот открыт, и списков тех, кто писал
боту и за кем следит, в нём быть не должно — ни в каком виде.

```
berg-creator/plenka         открытый: код, промпты, база связей
berg-creator/plenka-state   приватный: watches.json — кто за кем следит
```

Прятать адреса переписки шифром в открытом файле было бы самообманом: чтобы
прислать весть о релизе, адрес нужно восстановить, а значит ключ лежит рядом
с замком. Разделение хранилищ — честный вариант.

Настраивается двумя секретами в открытом репозитории:

| Секрет | Значение |
|---|---|
| `STATE_REPO` | `berg-creator/plenka-state` |
| `STATE_TOKEN` | fine-grained токен с правом **Contents: Read and write** на этот репозиторий |

Пока секреты не заведены, слежение просто выключено — остальное работает
как работало. Локально хранилище живёт в `data/private/`, и git его не берёт.

Подписка срабатывает мгновенно: её пишет живая дежурная смена. А рассылка идёт
следом за сбором новинок, раз в шесть часов, — весть о релизе уместна тогда,
когда релиз нашёлся, и торопиться тут некуда.

### Как о сервисе узнают

```bash
python -m src.setup --bot --publish      команды в меню, описание, строка в поиске
python -m src.setup --about --publish    описание канала — видно до подписки
python -m src.setup --card --publish     визитка с кнопкой «Разобрать свой вкус»
python -m src.setup --vk --publish       пост во ВКонтакте
```

Первые две команды применяются мгновенно и так же легко отменяются. Визитка
и пост во ВКонтакте по умолчанию только показывают текст: `--publish`
добавляется осознанно. Для ВКонтакте это особенно важно — ключом сообщества
пост публикуется, но не удаляется.

### Про скорость ответа

Ответ приходит не мгновенно: события забирает тот же опросчик, что и кнопки
модерации. В расписании стоит пять минут, но **GitHub это расписание
не гарантирует**: на бесплатном тарифе приватного репозитория запуски
разрежаются, и на практике между ними бывает час и больше. Плюс арифметика:
288 запусков в сутки по минуте — это ~8600 минут в месяц при бесплатных 2000.

Пока так, бот честно говорит, что плёнка проявляется не сразу. Чтобы отвечал
за секунды, нужен постоянно живущий процесс: `telegram.get_updates` уже
принимает `timeout`, то есть long polling код умеет — не хватает только места,
где его держать. Дешевле всего VPS за 200–300 ₽ в месяц.

### Откуда берутся факты

Источника два, и это принципиально — правило «ничего не выдумывать» осталось
прежним, просто выдумывать больше не приходится.

| Источник | Что даёт | Вес |
|---|---|---|
| `data/lineage.json` + `data/artists.json` | проверенные руками связи по тёмному звуку | главный |
| Last.fm | теги, похожие артисты, справка — **по любому исполнителю** | добирающий |

Курируемая база покрывает полторы сцены, и раньше на всём остальном бот отвечал
«такого нет». Теперь недостающее берётся из Last.fm: это настоящие данные,
а не догадки модели. Промпты знают о разнице в весе — теги Last.fm проставили
слушатели, поэтому это правда о том, как артиста слышат, а не приговор.
Отдельно оговорено, что похожесть не равна влиянию: «стоят рядом» и «один
вырос из другого» — разные утверждения.

Если молчат **оба** источника, бот честно говорит, что не знает, и предлагает,
с чего начать. Модель при этом не вызывается вовсе — до промпта дело не доходит.
Такие запросы копятся в `data/lineage_requests.jsonl`: это список, чем пополнять
базу, причём по реальному спросу, а не по догадкам.

Без `LASTFM_API_KEY` сервис работает по одной курируемой базе — ключ
необязательный, но с ним бот перестаёт быть узкожанровым.

Все выданные разборы ложатся в `data/service_log.jsonl` — материал для постов
вроде «разбор подписчика №23». В очередь канала они сами не попадают:
что публиковать, решаешь ты.

### Проверить, не трогая Telegram

```bash
python -m src.service --match "Bones, Sematary, Bladee"   # что нашлось в базе, без затрат
python -m src.service --try "Bones, Sematary, Bladee"     # полный разбор в терминал
python -m src.service --stats                             # расход лимитов
python -m src.card --verdict "текст" --artists "A, B"     # только карточка
```

Чтобы сервисом начали пользоваться, ссылку на бота надо повесить в описание
канала и в закреп — сам себя он не найдёт.

## Как менять канал под себя

| Что поменять | Где |
|---|---|
| **Тон и стиль постов** | `prompts/voice.md` — самый важный файл, правки видны сразу |
| Правила отдельной рубрики | `prompts/rubrics/*.md` |
| Кого отслеживаем | `data/artists.json`, потом `python -m src.resolve_ids --missing` |
| Связи для «Откуда ноги» | `data/lineage.json` — пополняется вручную, это ядро уникальности |
| Треки для «Между строк» | `data/subtext.json` |
| Памятные даты | `data/calendar.json` |
| Источники новостей | `data/feeds.json` |
| Как часто публиковать | `PUBLISH_INTERVAL_HOURS` в `src/config.py` |
| Доли рубрик | веса в `RUBRICS`, файл `src/config.py` |
| Тон разборов в боте | `prompts/service/*.md` |
| Лимиты разборов | `SERVICE_DAILY_USER`, `SERVICE_DAILY_TOTAL` в `src/config.py` |
| Вопросы под постами | `QUESTIONS` в `src/comments.py` |

### Откуда канал знает, как звучит альбом

Ниоткуда — и это ограничение, из которого сделан весь разговор о музыке.
Модель альбом не слушала, поэтому любое «мрачные биты и атмосферные сэмплы»
было бы выдумкой, а выдумку в музыкальном канале ловят на первом прослушивании.

Вместо этого сборщик забирает у iTunes и Deezer **треклист**: названия треков,
длину каждого, общий хронометраж, гостей и жанр по версии магазина. Это не звук,
но это фактура, по которой видно устройство релиза — а из устройства уже
следуют выводы, и они проверяемые:

> Пятнадцать треков за тридцать одну минуту, самый длинный не дотянул
> до четырёх с половиной, в середине интерлюдия на сорок девять секунд.

Правила такого разговора живут в `prompts/voice.md`, раздел «Канал пишет
про музыку, а не про факт её выхода». Красная черта там одна: что нельзя
проверить по данным — того в посте нет.

Релизы, найденные до появления треклистов, дозагружаются отдельно:

```bash
python -m src.collect --backfill-tracks
```

Сработает не для всех: у андеграундных артистов поиск в магазинах слабый,
а неточное совпадение отбрасывается намеренно — чужой треклист в посте хуже,
чем его отсутствие.

### Почему две рубрики заполняются вручную

`lineage.json` и `subtext.json` — курируемые базы, и это сделано намеренно.
Тексты песен и точные сведения о том, кто у кого что сэмплировал, автоматически
брать неоткуда: легальных источников нет, а придуманная цитата или выдуманный
год убивают доверие к каналу быстрее, чем что-либо ещё. Поэтому модели
разрешено пользоваться только теми фактами, которые лежат в этих файлах.

## Сколько стоит

| Статья | Цена |
|---|---|
| GitHub Actions | бесплатно (расход ~400 из 2000 минут в месяц) |
| iTunes, Deezer, YouTube, RSS | бесплатно, без ключей |
| Last.fm | бесплатно |
| **Claude (Anthropic)** | основной генератор, платный: $5 за млн входных токенов, $25 за млн выходных |
| GigaChat | запасной генератор: 1 млн токенов бесплатно, дальше рублями по расходу |

Канал тратит ~2800 токенов на пост, то есть около 670 тысяч в месяц при
восьми постах в день. На Клоде это порядка $5–10 в месяц: посты пишутся
не по одному, а пачкой через Batch API (ровно вдвое дешевле), а общая часть
промпта — голос канала — кэшируется и на повторных запросах читается
примерно за десятую часть цены.

### Смена генератора текстов

Две строки в `.env` — основной генератор и запасной:

```
LLM_PROVIDER=anthropic   # Claude, платно, пишет лучше всех — по умолчанию
LLM_PROVIDER=gigachat    # Сбер, работает в России
LLM_PROVIDER=gemini      # Google, бесплатно, но в России недоступен

LLM_FALLBACK=gigachat    # кто пишет, если основной не ответил (пусто — никто)
```

Запасной включается сам и только на технических отказах: кончились деньги,
отвалилась сеть, упал сервис. Осознанный отказ модели («материал не тянет
на пост») фоллбек не поднимает — это не поломка, а решение. Переход
пишется в лог запуска строкой `WARNING llm`.

Проверить генератор и посмотреть пробный пост:

```bash
.venv/bin/python -m src.check_llm --sample
```

Промпты и рубрики от провайдера не зависят — меняется только генератор.
Это сделано, чтобы можно было сравнить качество текстов на своём материале
и решить, стоит ли платить, а не гадать заранее.

## Особенности ВКонтакте

Кросспостинг включается сам, как только появляется `VK_TOKEN`, и молча
пропускается без него — вторая площадка не должна мешать основному каналу.
Ошибка публикации во ВКонтакте тоже не роняет запуск: пост в Telegram к тому
моменту уже вышел.

Что нужно знать про ключ сообщества:

- **Публиковать он может, а удалять и закреплять — нет.** ВКонтакте запрещает
  групповой авторизации и `wall.delete`, и `wall.pin`. Всё, что ушло в группу,
  убирается и закрепляется только вручную. Это ещё один довод за то, чтобы
  держать модерацию включённой.
- Тип приложения «Standalone» из интерфейса ВКонтакте убран — ключ берётся
  прямо в настройках сообщества, никакого OAuth не нужно.
- Разметка Telegram в постах ВКонтакте не поддерживается: теги вырезаются,
  а ссылки разворачиваются в вид «текст: адрес».
- Опросы пока публикуются только в Telegram — во ВКонтакте они устроены иначе.

## Что автоматизация не сделает

Она даёт бесперебойный контент, но не подписчиков. Первую тысячу приносят
посевы в смежных каналах, взаимопиар или реклама — это либо деньги, либо
ручная работа. Никакой генератор постов этого не заменит.

ПРОЯВКА тут помогает, но не решает: она даёт человеку повод показать канал
друзьям, а вот привести к боту первую сотню людей всё равно придётся руками.
Инструмент без аудитории работает вхолостую.
